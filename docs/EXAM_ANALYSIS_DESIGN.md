# 题目分析、法律解释与讲解

## 输入与分析范围

`mode=analyze` 支持完整选择题、文本案例、当前题目的追问和条件变更。`auto` 根据选项格式、关键词及当前会话路由，`lookup` 明确使用普通法规查询。题目存在影响判断的 OCR 歧义时追问，不静默改写。

审题为每个争点标记 `analysis_type`：直接规则 `direct`、概括规范适用 `subsumption`、跨条文解释 `systematic`、条件与例外判断 `condition_application`。同题各选项可以采用不同方法。判断选项所需的争点标记为 `purpose=answer`；学生明确另外提出的讲解问题标记为 `explanation`，不增加未要求的扩展事项。

## LangGraph 工作流

```text
prepare → exam_intake → 澄清 / 提示 / plan_tools
plan_tools → execute_tools → assess_evidence
assess_evidence → 必要规则缺口且有预算：plan_tools
assess_evidence → exam_analyze → 直接判断：exam_render
exam_analyze → 解释性判断：exam_review
exam_review → 必要规则缺口且有预算：plan_tools（审核触发最多一次）
exam_review → exam_render → validate_citations → finish
```

审题、前提检查和分析任一环节识别到解释需求，都会触发审核；未完成审核的解释性判断不作为确定结论输出。新增回查共用原检索轮数、工具数、模型调用数和时间，不开启新预算。原普通法规查询路径保留。

## 规范前提与适用结构

前提检查逐争点记录状态：`direct_supported`、`interpretation_ready`、`missing_rule`、`missing_fact`、`interpretation_disputed`、`version_gap`。取得一般规则、可以解释其范围时可进入分析；没有逐字列举具体程序名称，不自动视为缺少依据。`interpretation_ready` 不是最终审核通过。

选择题每项分析包含：

| 字段 | 内容 |
|---|---|
| `support_type` | 本项判断采用的分析方式 |
| `rule_basis` | 当前证据 ID、连续逐字原文 `source_quote`、规则概括 `rule` |
| `interpretation` | 规范含义和适用范围的简明说明 |
| `application` | 本题主体、行为或事实与规则的对应 |
| `boundary_check` | 特别规定、例外和法律后果边界 |
| `missing_premises` | 真正缺少的必要前提 |
| `verdict` | 正确、错误或不能确定 |

程序检查原文与证据归属、判断与争点关联、选项完整性及确定判断是否仍带必要缺口。单独的模型请求批量审核整题适用摘要，检查主体扩大、条件遗漏、忽略特别规定、由原则直接推导处罚等问题。审核不读取标准答案，不直接改写选项答案。引用真实条文与审核通过均不能自动保证法律推论正确。

审核状态包括 `approved`、`missing_rule`、`missing_fact`、`disputed`、`invalid_application`。只有缺规则且提供明确查询目标、预算允许时才回查；适用错误和事实缺口不通过重复检索掩盖。被否决的候选结论、解释和适用摘要不会作为确定结果返回给学生。

## 答案与讲解分开完成

`answer_complete` 表示所有必要选项判断已核实，`explanation_complete` 表示本轮讲解已获得支持。`complete` 为二者同时成立。额外讲解存在缺口时可以保留已核实的答案，整体响应标记 `limited` 并说明限制。

程序根据“选正确／选错误”汇总选项。关键选项未知、必要事实缺失或单选出现多个候选时不输出完整选项集合。页面在“原文规定与本题适用”中区分原文、规范解释、具体适用和边界。

## 方法卡与数据隔离

章节方法包来自显式提供的开发材料。通用解释方法卡包括概括规范适用、一般与特别规定、条件及法律后果。内置卡仅提供通用检查程序；`build_interpretation_methods.py` 可从开发解析提炼带来源 ID 的方法包。每类最多选八道开发题，优先覆盖不同章节；不是全量训练或模型权重微调。

每题最多两张章节卡、一张解释方法卡，共用方法上下文字符上限。方法卡不是法律证据。在线不读取开发题文件、不按相似题取得标准答案。

章节方法与解释方法各有独立版本；内容哈希校验通过后加载，全部提炼成功才原子切换解释方法指针。会话分别绑定首次使用的方法版本；更新方法后新建会话生效，恢复旧会话需要保留旧包。缺少提炼包时使用内置解释方法。

教材标准答案是离线评分正确标准。开发、验证、测试应按相似题组事先划分；导入器只接受 development，保留集不进入方法提炼。原始题目、请求预览、派生方法包和报告位于 Git 忽略目录，目录隔离不等于权限隔离。

## 多轮与提示

会话保存题目 ID、revision、题设及知识库快照。修改条件增加 revision，重置候选分析和审核结果；追问沿用题目 ID 并重新核实相关依据，旧答案不是证据。明确切换为法规查询后，自动追问不会被旧题接管。

`hint` 提供确定性的审题检查提示，不执行法律检索、解答生成或解释审核；API 和会话公开结果不返回选项真假、答案集合及内部候选。当前提示不是逐步推导式个性化辅导。

## 预算与运行限制

默认三轮检索、每轮两个工具、八次模型调用、一次分析结构修复、180 秒总预算。解释审核触发的补查最多一次，并为补查后的前提检查、分析和审核预留调用额度；剩余时间不足 `EXAM_COMPLETION_RESERVE_SECONDS`（默认60秒）不再补查。该预留是调度判断，不是进程级强制截止，平台请求超时与 SDK 重试仍受原有设置约束。

证据默认最多16个完整片段、10000字符，优先保留精确目标，再容纳语义召回。分析与审核只接收最终保留证据，不重复携带旧工具正文。方法上下文默认3000字符。

只处理文本；图片、复杂公式和表格需人工核对。资料版本以知识库清单为准，不自动核验现行性。已接入的国际条约范围见[国际资料说明](INTERNATIONAL_SOURCES.md)；缺少司法解释、缔约声明或未收录附件等必要材料时仍可能无法完整作答。

## 评测

`evaluate_exam.py` 只将题干、选项及题目文件本身的题型送入解题服务，教材答案留在评分侧。记录精确选项匹配、答案完成、讲解完成、解释审核状态、争点覆盖和引用完整性；这些指标不能相互替代。

`evaluate_interpretation.py` 使用 `eval/interpretation_cases.json` 中明确标注的自拟正反例，结果记录为 authored_fixture，不计入教材准确率。检查概括规范适用和越界推断，并记录代码及方法版本、引用和规则引文完整性。自动化模拟测试验证流程约束；法律解释质量还需真实模型结果与人工核验。开发样例参与方法提炼，其结果不代表保留集表现。
